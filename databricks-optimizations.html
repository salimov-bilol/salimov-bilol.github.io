Comprehensive Guide to Databricks Performance Optimization 🚀

This guide lists key optimization techniques, providing the SQL commands or Spark configurations needed for implementation.

1. Engine & Runtime Optimizations (DBR & Photon)

Features that accelerate the query processing engine itself.

Technique Implementation Description Primary Benefit
Photon Engine Enabled via cluster configuration: "Use Photon Acceleration" checkbox. A C++ native, vectorized query engine that drastically speeds up SQL and DataFrame operations. Up to 2x to 8x faster performance for SQL workloads by avoiding JVM overhead.
Delta Caching (Disk Cache) Automatic on optimized node types; explicitly enable with:
SET spark.databricks.io.cache.enabled = true;		 Stores copies of remote data files (Parquet/Delta) on the local SSDs of the worker nodes. Accelerates repeated reads of "hot" data, minimizing I/O latency from cloud storage.
Adaptive Query Execution (AQE) Enabled by default in modern DBR:
SET spark.sql.adaptive.enabled = true;		 Spark dynamically re-optimizes the query plan during runtime (e.g., handles skew, switches joins). Automatically fixes data skew and selects the best join strategies without manual tuning.
Result Caching Automatic in Databricks SQL Endpoints; no command needed. Caches the results of entire queries in the Databricks SQL layer. Provides instantaneous results for identical queries, critical for BI dashboards.

2. Data Layout & Indexing (Delta Lake)

Techniques focused on optimizing the physical storage layout to reduce data scanning.

Technique Implementation Description Primary Benefit
Z-Ordering Run the command:
OPTIMIZE table_name ZORDER BY (col1, col2);		 Multidimensional clustering that physically co-locates related data values from chosen columns. Significantly improves query performance on range-based filters by enabling powerful data skipping.
Liquid Clustering Defined at table creation:
CREATE TABLE ... CLUSTERED BY (col1, col2);
Maintenance via:
OPTIMIZE table_name;		 A newer, flexible clustering method that automatically adapts to diverse query patterns. Acts as a superior replacement for partitioning and Z-Ordering, optimizing a wide variety of filters.
File Compaction Run the command:
OPTIMIZE table_name;		 Consolidates many small data files into fewer, larger files (typically 1GB) for efficient reading. Solves the "small file problem," reducing metadata overhead and speeding up file reads.
Data Skipping Automatic when using Delta Lake. No command needed. Uses min/max statistics stored in the Delta Transaction Log to skip reading entire files. Reduces I/O and query time by ensuring Spark only reads necessary files.

3. Automated & Code Optimizations

Techniques that automate maintenance or focus on efficient code practices.

Technique Implementation Description Primary Benefit
Partitioning Strategy Write command:
df.write.partitionBy("date").saveAsTable(...)		 Partitioning data on a medium-cardinality column (e.g., date, region). Must be balanced to avoid creating too many tiny files. Enables partition pruning (skipping directories), drastically reducing the volume of data scanned.
Optimized Writes Spark Session Config:
SET spark.databricks.delta.optimizeWrite.enabled = true;		 Dynamically sizes Spark partitions just before the write to produce files of optimal size (e.g., 128MB). Ensures data is written in an efficient layout, benefiting subsequent reads.
Auto Compaction Spark Session Config:
SET spark.databricks.delta.autoCompact.enabled = true;		 Automatically triggers a minor file compaction immediately after a successful write operation. Proactively handles small files generated by frequent `INSERT` or `UPDATE` operations.
Broadcast Joins Use a Hint in SQL:
SELECT /*+ BROADCAST(dim_table) */ * ...		 Avoids costly data shuffle by sending a small DataFrame (< 1GB) to all executor nodes. Eliminates the costly network shuffle for joining small tables with large fact tables.
UDF Avoidance Code Practice: Use native functions instead of Python UDFs.
df.withColumn("new", F.col("old") + 1)		 Replaces slow UDFs with built-in functions optimized by Photon. Avoids costly serialization/deserialization overhead, dramatically increasing speed.
`COALESCE` / `REPARTITION` DataFrame function:
df.coalesce(10) (efficiently decrease)
df.repartition(100) (shuffle to balance)		 Manually adjusts the number of DataFrame partitions to improve I/O efficiency or reduce skew. Prevents the "small file problem" at write time (`coalesce`) or eliminates data skew (`repartition`).
